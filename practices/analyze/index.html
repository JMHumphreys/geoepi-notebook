Analyze

Specify, execute, and trace exploratory or planned analyses before future validation.

Analyze is more than obtaining a numerical answer or successfully running code. It connects a scientific or operational question to an analysis-ready dataset, a stated method, recorded settings, a particular execution, generated outputs, and candidate results that can be checked in the Validate stage.

Analyze boundary

Analyze begins when a staged or derived dataset is recorded as ready for analysis or ready for analysis with documented limitation. The limitation must travel with the analysis record and outputs. Analyze may clarify the objective, define the target, record methods and settings, run scripts or models, preserve warnings and incomplete work, and trace important results.

Analyze does not complete model checking, convergence assessment, residual diagnosis, calibration, predictive-performance assessment, external validation, robustness or sensitivity conclusions, simulation verification, uncertainty adequacy, scientific interpretation, publication approval, or operational approval. Those decisions belong to Validate or later stages.

Analyze workflow

  1. Confirm the dataset is ready for analysis.
  2. State the analysis question or practical objective.
  3. Define the quantity, contrast, prediction, pattern, or simulation outcome of interest.
  4. Label the work as exploratory, planned, sensitivity, or post hoc.
  5. Record the method, variables, settings, and intended outputs.
  6. Run the analysis from a documented starting point.
  7. Record the execution, including warnings and failures.
  8. Link important results to their data, code, settings, run, and output.
  9. Record changes made after earlier results were viewed.
  10. Decide whether the analysis is ready to enter Validate.

A candidate result is an output that has been produced and recorded but has not passed the future Validate stage. A successful analysis run shows that the recorded procedure produced an output. It does not establish that the method was appropriate, the model fit adequately, the predictions are accurate, or the scientific conclusion is justified.

Evidence and interpretation

The draft workflow is informed by the existing resource catalog, including The Turing Way, Good Enough Practices in Scientific Computing, the TIER Protocol, FAIR Principles for Research Software, RDMkit, DataONE, and Ecological Forecasting Initiative guidance. These sources support clear objectives, recorded code and settings, reproducible execution, and traceable results. They inform this draft workflow but do not establish GeoEpi or institutional policy. Access date: 2026-08-06.

Ready-for-validation gate

The safe starting status is not ready for validation. Use only these statuses:

  • not ready for validation
  • ready for validation
  • ready for validation with documented limitation

An analysis may enter future Validate only when:

Run completion belongs to the run record. Candidate selection belongs to result records and the analysis-level readiness decision. Passing this gate means that the analysis has been specified, executed, and recorded well enough to undergo validation. It does not mean that the analysis has passed validation.
